# Premium editorial and interactive portfolio research

**Research date:** 2026-08-28
**Scope:** current premium portfolios and digital editorials, production motion, hierarchy systems, performance, and accessibility.
**Local context reviewed:** the current Foyer, Alcove, AI Desktop Pet, Keyscape, Earlier Experiments, Useful Things, bottom route, and the pointer/parallax implementation in `index.html`, `styles/museum.css`, and `scripts/museum.js`. No visual acceptance claim is made here; these are research-backed hypotheses for the implementation and screenshot review lanes.

## Executive finding

Grand does **not** mean adding more simultaneous ornament. The strongest work uses a clear editorial skeleton, one authored world or material metaphor, and a small number of unusually well-made interactive objects. Detail is concentrated around the focal story; secondary information is quieter, flatter, and typographically exact. Motion is causal and local: one object reacts because the pointer touched its field, a transition marks a change of context, or a detail reveals how the project works. Whole-page pointer parallax and unrelated ambient loops read as instability, not craft.

The target for this portfolio should therefore be a **kinetic cabinet of software instruments** rather than a museum of themed cards. The shared system is typography, spacing, navigation logic, accessibility, and motion timing. Each room earns its own composition, material, and interaction from the software it presents: bound paper for Alcove, a desktop habitat for AI Desktop Pet, optical/electrical instrumentation for Keyscape, preserved prototypes for the archive, and working implements for Tools.

## Convergent practices

1. **Begin with a thesis object, not a generic layout.** Current award and practitioner sources repeatedly describe a portfolio as a place, stage, instrument, or coherent world. A visitor should be able to name the Foyer's central object after one glance.
2. **Use one dominant scale break.** Large display type or a hero object establishes priority; two or three smaller typographic tiers then carry context. Equal-sized cards, labels, ornaments, and media create visual static.
3. **Build detail from subject-specific material logic.** Paper should fold, tabs should pull, felt should drag, light should refract, and a companion should notice. Texture pasted onto a generic panel does not produce authorship.
4. **Give every movement a job.** The best case studies describe motion as attention direction, state change, pacing, or explanation. Ambient behavior can establish life, but each object gets at most one quiet idle behavior plus one direct response.
5. **Keep novelty bounded.** Physics text, cursor distortion, particle trails, and 3D worlds work when confined to a signature moment. Project facts, navigation, and actions remain stable and readable.
6. **Create hierarchy with fields, margins, and anchors instead of card grids.** Full-bleed media, inset plates, editorial captions, marginalia, ledgers, spines, timelines, and object labels can separate information without wrapping every thought in a rectangle.
7. **Make mobile a different composition, not a shrunken desktop.** Strong production cases remove costly/WebGL layers while preserving the idea through typography, still imagery, or a simpler local interaction.
8. **Treat reduced motion as art direction.** Keep the material, state, and hierarchy; remove travel, inertia, parallax, and nonessential auto-motion. A static version should feel intentionally composed rather than disabled.

## Concrete hypotheses for this portfolio

### Shared motion and hierarchy

- Delete the current page-wide `data-depth` pointer parallax path. Replace it with an opt-in component motion registry: each registered object owns its hit/influence region, physics state, maximum displacement, return behavior, keyboard/touch equivalent where relevant, and reduced-motion state.
- Use one `requestAnimationFrame` owner for pointer-reactive objects. Read pointer state once, update only objects whose expanded bounding boxes contain the pointer, write only transforms/opacity/custom properties, and stop the loop after every spring rests.
- Use a three-layer information hierarchy in each room: **thesis** (one title or object), **proof** (the real demo or the central interactive model), and **evidence** (facts, mechanics, source link). Evidence should live as captions, marginalia, instrument markings, or a ledger—not repeated pill/card components.
- Set a density budget: one dominant object; one supporting interactive cluster; no more than two decorative motion systems visible at once; one still zone around body copy. If everything is intricate, nothing reads as precious.
- Preserve a shared typographic rhythm but vary composition aggressively. Shared typography is the family resemblance; duplicated two-column page templates are not.

### Foyer

- Make the hero a **maker's observatory/workshop**. The kitten remains the emotional anchor; an intricate suspended light instrument becomes the visual anchor; the thesis is the verbal anchor. These three should form a triangular reading path and occupy the currently vacant center.
- Replace the three plain ceiling bulbs with 3–5 constructed fixtures: etched-glass lenses, brass/copper arms, counterweights, prisms, apertures, and filament paths. Build each fixture as a coherent SVG/DOM rig with a fixed canopy, bounded pendulum joint, lens rotation, and refracted light cone.
- Use local pointer physics: a pointer crossing a fixture's influence radius transfers a small impulse based on pointer velocity and approach angle. The joint uses damping and a hard angular limit; the canopy and page never move. Fixtures settle completely rather than looping forever.
- Replace cheap orbit circles/runners with one authored optical diagram: a fine engraved trajectory, small refracting prisms, and a light filament that connects real themes (books, companions, light, tools). It should explain the portfolio taxonomy, not behave as background confetti.
- Split the thesis into semantic phrase spans. Only the nearest phrase inside a tight radius reacts; cap translation to roughly 4–8 px and rotation to about 1 degree, apply distance falloff, then spring home. Never alter layout width, line wrapping, or the other lines.
- Keep the kitten's direct behaviors—eye tracking and speech—but do not make the whole kitten tilt in response to a pointer anywhere in the room. Its reaction field should be the kitten/speech cluster only.
- Replace the current generic index cards with a narrow **work index ribbon** or engraved floor-plan legend. Each destination uses a project-derived mark and a concise proof point; hover reveals one local mechanical detail, not a universal lift-and-shadow animation.

### Alcove

- Compose Alcove as a **working book conservatory** rather than the same copy-left/demo-right exhibit. Let the real demo occupy the reading desk; a vertical binding/spine carries title and facts; build notes appear as margin flags aligned to events in the demo.
- Rename “Annotate the demo” to a visitor action that describes the result. Best hypothesis: **“Read the build notes”** / **“Close the build notes.”** Alternative if the visual emphasizes construction: **“Open the binding”** / **“Close the binding.”** Avoid verbs that sound like the visitor will edit the project.
- When build notes open, do not float three generic bubbles over the film. Pull out page flags or margin slips attached to exact regions/timestamps; the media remains fully legible. On keyboard/touch, the same control opens a stable ordered note list.
- Let paper mechanics own motion: page-edge riffle, bookmark settling, shelf labels sliding by a few pixels, and a single page-turn-derived transition. Avoid particles, glows, or the Pet/Keyscape motion language.

### AI Desktop Pet

- Recompose the room as a **living desktop habitat**, not an Alcove recolor. Make the demo a monitor/window field; let the behavior trace become an environmental route across taskbar, window edge, cursor, and conversation zone.
- Replace “Call the creature” with **“Say hello”** (recommended) or **“Invite it over.”** The former is natural, short, and accurately predicts a social response. The response should be a short entrance/acknowledgement plus an accessible live message, not a generic room shake.
- Give the pet a local awareness field. When the pointer enters the monitor habitat, the pet notices, chooses among a few bounded behaviors, and returns to idle. Do not make surrounding copy or media parallax.
- Use warm desktop light, glass edges, taskbar tracks, clipped windows, and small memory/conversation traces. Do not reuse shelves, note cards, ledger styling, or Alcove's pink paper material.

### Keyscape

- Treat Keyscape as a **dark optical instrument / light-score console**. The hero proof is the mapping from input to physical key coordinates to light propagation, rendered as a spatial score rather than another set of cards.
- Rebuild the bottom route for this room as smoked glass, blackened metal, and restrained emissive key-lines. The entire outer bar—not merely the selected button—must remain dark. Active state should look electrically coupled to the Keyscape room; inactive destinations stay legible without beige/pastel surfaces.
- Let pointer proximity refract a local beam, and let A/S/D/F or button presses propagate through the key geometry with distinct physical signatures. Background, title, demo frame, and bottom chrome remain stable.
- Use fewer but richer lights: controlled bloom, layered falloff, a faint etched coordinate grid, LED ghosting, and real key positions. Avoid rainbow gradients, equalizer wallpaper, and unrelated floating dots.

### Earlier Experiments

- Replace small line-icon tabs with a **specimen archive**: each project gets one unmistakable, project-derived object at meaningful scale (NPC conversation stage, presenter/storyboard apparatus, CupcakeAGI sensory core). Selection moves or unfolds the object into the central stage.
- Keep a stable archive index and source metadata; only the selected artifact receives high detail and motion. This gives strong hierarchy without turning three equal cards into visual competition.
- Let each artifact use its own reveal grammar while the enclosing archive uses one material system (drawers, sleeves, labels, or conservation mounts). Art should communicate before the label is read.

### Useful Things

- Replace tool cards with a **maker's tool cabinet** whose controls are recognizable implements, not mini illustrations in boxes: Email Briefing as a sorting/signal desk, Gifsmith as a film gate/timeline forge, Compendium as an indexed evidence wheel, Transparency as stacked optical panes.
- Each selector should manipulate the central apparatus—feed, turn, focus, align—so the action previews what the tool does. Selection must also have normal tab semantics, visible focus, and a direct label.
- Preserve practical clarity: tool, problem removed, three-step mechanism, real demo, source. Put those roles into a work-surface composition; do not hide essential facts behind hover.

## Review gates derived from the research

The redesign is not visually accepted until all of these are true:

- A full-frame screenshot has one obvious first, second, and third attention target in every room.
- Cropping the text out of a room still leaves an object/material language specific enough to identify the project.
- Cropping the art out still leaves a readable typographic hierarchy and direct actions.
- Slow pointer movement, fast passes, direction reversals, and pointer exit never shift the page frame or unrelated components.
- Every spring has bounded displacement and settles; no local reaction accumulates drift.
- Keyboard, touch, coarse-pointer, 200% zoom, short-height, and reduced-motion layouts preserve content and action meaning.
- Motion pause stops nonessential automatic motion. Media playback remains separately controllable.
- A performance trace shows no continuous animation work for off-screen rooms and no layout work in the pointer loop.
- Decorative detail can be removed in one pass without breaking comprehension; if it cannot, it is probably carrying information and needs semantics.
- The final close-up review checks fixture joints, optical highlights, icon silhouette, small-type spacing, borders, compositing seams, focus rings, and bottom-bar material—not only the full frame.

## Evidence synthesis: where sources agree and disagree

- **Agreement:** expressive portfolios need a strong point of view, clear type, local interaction, and tiny finishing details. Accessibility/performance sources add the necessary constraint: those details must be bounded, stoppable, input-independent, and cheap per frame.
- **Agreement:** detail is most credible when it comes from the subject's material or behavior. This is why a page flag belongs in Alcove, a window route belongs in Pet, and a refracted LED field belongs in Keyscape.
- **Productive tension:** award sources celebrate immersion and experimentation, while usability/design-system sources warn against obscuring structure. Resolve this by putting spectacle in one signature stage and keeping titles, actions, project evidence, and navigation conventional enough to scan.
- **Productive tension:** some production sources support scroll choreography, but the existing portfolio is a fixed horizontal world. Native scroll timelines or ScrollTrigger should be used only in actual scroll containers or deliberate internal sequences, not to add another navigation model.
- **Evidence limitation:** awards and producer case studies demonstrate craft and implementation patterns, not universal usability or causal business value. W3C, platform documentation, and measured performance guidance set the acceptance floor; rendered review with this portfolio's real content decides the art direction.

## Recommended testable defaults

These are starting hypotheses for visual tuning, not standards:

- Headline phrase: 120–160 px influence radius; 4–8 px maximum displacement; at most 1 degree rotation; near-critical return; stable outer layout box.
- Pendant/fixture: 140–220 px influence radius; impulse from smoothed pointer velocity; 3–6 degree hard angular limit; independent mass/damping per fixture; rest threshold that stops rAF.
- Local direct feedback: begin inside roughly 70–150 ms; full object settlement typically within 350–700 ms, adjusted by perceived material weight.
- Pointer scheduler: one latest sample and one rAF loop; cached geometry; no DOM-wide query or React/render-state update per pointer event.
- Visibility: no animation work for inactive/off-screen rooms; mobile/coarse pointer receives intentional still composition; reduced mode removes spatial motion.
- Interaction performance: target INP at or below 200 ms at the 75th percentile and verify both 60 Hz and high-refresh displays.
